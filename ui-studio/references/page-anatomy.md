# Page anatomy by category

Real sites are built around the category's own content. Use the matching entry to decide sections and where the main action lives. When the person hasn't supplied a section's content, show its shape with an obvious sample to replace ("Your dish name — short description — $0"), never a fact a visitor could believe.

**Every page:** the navigation names the category's own action (Order, Book, Call, Tickets, Start free), the first screen shows the real thing (the food, the work, the product, the date), and proof comes in the category's own form, not a generic stats band.

## Food, café, bakery, restaurant
Action: order/pre-order, book a table, or visit. Hours and address reachable from the first screen. Sections: what's on the counter or menu (names, short descriptions, prices if given), what makes it theirs (the baker, the ingredients, the story in two sentences), how to order and pick up, find us (map link, hours, phone). Ends with hours, address and the action again.

## Local service (plumber, salon, clinic, tutor, trainer)
Action: call, book, or request a quote; phone number tappable on mobile. Sections: services with prices or "from" prices if given, the area served, how it works (only if it's truly a sequence), credentials stated plainly, real reviews only if supplied, booking/contact. Ends with contact and hours.

## Professional / consultant / freelancer
Action: a plain "Email me" / "Book a call". Sections: who it's for and the problem solved (one sharp sentence), selected work or case notes (client, problem, outcome — only real ones), how engagements work, about (one paragraph, real photo slot), contact. No invented logos or metrics.

## Product / software / app
Action: start free, download, or book a demo, with terms in one line under the button. Sections: the product doing its job (real screenshot or a faithful built example), 2–4 named moments of what it does (shown, not icon cards), how it fits (integrations, a code sample for developers), pricing if given, questions. Ends with the action again.

## Event, workshop, course
Action: register / tickets. Date, time and place are the headline material. Sections: what you'll get or learn, schedule, who's teaching or speaking (only real names), price and what's included, venue/online details, questions. Ends with register again.

## Nonprofit, community, club
Action: join, volunteer, donate, or come to the first meeting. Sections: what you do, shown concretely; when and where; how to take part (options as plain rows); first-visit guidance; contact.

## Portfolio / creative
The work is the page: a list or grid of projects with real titles and images, one opened in more depth; a short "what I do"; contact. The interface stays quiet.

## Article, guide, documentation (Read mode)
Comfortable measure (60–70ch), clear heading hierarchy, a table of contents for long pages, generous spacing, code blocks styled and copyable, nothing competing with the text.

## Dashboard, tool, admin (Operate mode)
Start from the task: what does the user check or change most often? Put that first. Familiar patterns (left or top nav, tables with sortable headers, filters above results). Dense but calm: 13–14px UI text is fine, tabular numbers, aligned columns, clear empty/loading/error states, one accent for primary actions and status colours used only for status. No marketing flourishes.

## Form or multi-step flow
One column, labels above fields, helpful hints under fields, errors next to the field in plain words, the primary button named for the result ("Create account"), progress shown only if more than two steps.
